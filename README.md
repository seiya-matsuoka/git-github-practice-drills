Git / GitHub の操作を、実務で遭遇する場面を想定したドリル形式で練習するためのリポジトリ。  
単独のコマンドだけを確認するのではなく、複数の操作を組み合わせた課題に取り組み、作業前の確認から変更、コミット、同期、履歴整理、トラブル対応までを一連の流れとして扱う。

このリポジトリは、以下の役割を兼ねている。

- Git / GitHub 操作ドリルの課題置き場
- 実際に行った commit / branch / merge などの学習記録
- シチュエーションを再現するための練習用ファイル置き場
- Git の状態確認と操作を反復するための教材

> コマンドを覚えることだけでなく、現在の状態を確認し、状況に応じた操作を選べるようになることを重視している。

---

## 学習目的

このリポジトリでは、主に次の内容を目的として学習を行う。

- Git の現在状態を `status` / `diff` / `log` などから読み取れるようにする
- 変更内容を確認し、意味のある単位でステージング・コミットできるようにする
- branch の作成、切り替え、merge、削除までの流れを扱えるようにする
- conflict 発生時に状態と競合箇所を確認し、落ち着いて解消できるようにする
- `restore` / `reset` / `revert` / `reflog` などを状況に応じて使い分けられるようにする
- `stash` を使い、作業途中の変更を退避して別作業へ切り替えられるようにする
- remote / push / fetch / pull / tracking branch の関係を理解する
- GitHub Flow と Pull Request の一連の流れを確認する
- 操作を実行する前後で、Git の状態がどのように変わったかを確認する習慣を身につける

---

## ドリルで扱う内容

このリポジトリでは、主に次のような内容を扱う。

- 作業状態、変更ファイル、差分、履歴の確認
- ステージング、コミットの作成・分割・修正
- branch / merge / conflict
- `.gitignore` と tracked / untracked
- stash を使った作業の退避と復帰
- 変更の取り消し、部分的な取り込み、履歴からの復旧
- remote / push / fetch / pull
- GitHub Flow / Pull Request

各ドリルでは、これらの操作を1つずつ単独で行うのではなく、開発作業を想定した複数の手順として組み合わせている。

## ドリル文書の構成

`drills/` 配下の各Markdownドキュメントは、基本的に次の項目で構成している。

### 想定シチュエーション

実務や開発作業を想定し、どのような状況で何を行う課題かを記載する。

### この課題の目的

ドリルを通して確認する Git / GitHub 操作や、身につけたい考え方を記載する。

### 使用する主な操作

課題で扱う操作の種類を記載する。  
具体的なコマンドだけでなく、差分確認、ステージング、履歴確認などの作業も含む。

### 事前状態

課題を開始するときのブランチ、作業ツリー、対象ファイルなどの状態を記載する。

### 課題内容

実際に行う変更内容や、最終的に作りたい状態を記載する。  
ファイル編集が必要な場合は、変更箇所と変更内容も確認できる形で記載する。

### 作業の流れ

課題に取り組む順番を記載する。  
具体的なコマンドをなるべく示さず、何を確認し、どのような操作を行うかを中心にまとめる。

### 完了条件

課題完了時に、ブランチ、ファイル、コミット、作業ツリーなどがどの状態になっていればよいかを記載する。

### 解答例

課題内容を実際に進める場合のコマンド、ファイル編集、表示例、出力例を順番に記載する。  
各コマンドの直後に結果例を配置し、操作による状態変化を追いやすい形にしている。

### 学習ポイント

コマンドや表示結果と対応させながら、課題で特に確認したい点を記載する。

### 補足

別の操作方法、注意点、実務での使い分けなど、課題内容を理解するための補足を記載する。

## 学習の進め方

基本的な進め方は次の通り。

1. `drills/` 配下の対象ドリルを開く
2. `想定シチュエーション`、`課題内容`、`作業の流れ` を確認する
3. `解答例` を見ずに、まず自分で操作方法を考える
4. `practice/` 配下の対象ファイルを編集・追加する
5. `git status` / `git diff` / `git log` などを使い、作業状態を確認しながら進める
6. 詰まった場合、または課題完了後に `解答例` を確認する
7. 実際のコマンドと表示結果を照らし合わせる
8. `学習ポイント` を読み、操作の目的や状態変化を確認する
9. commit / branch / merge などの履歴をリポジトリに残す

課題文の前半は、自力で取り組むための情報として使用する。  
解答例は、操作方法が分からない場合の確認、または完了後の答え合わせとして使用する。

`practice/` のファイル編集自体が主な学習目的ではない。  
ファイルの変更を題材として、Git の状態を読み、適切な操作を選び、履歴として残すことを目的とする。

## 使用環境・ツール

- Git
- GitHub
- Git Bash

Git の操作は、基本的に CLI で行う。  
GitHub を扱うドリルではリモートリポジトリ、branch、Pull Request などの GitHub 上の操作も行う。

コマンドの出力、パス、コミットIDなどは実行環境や履歴によって異なる。  
ドリル文書の表示例は、実際の環境に合わせて読み替える。

## リポジトリ構成

主要な構成は次の通り。

```text
.
├─ drills/
│  ├─ 001-xxx.md
│  ├─ 002-xxx.md
│  └─ ...
│
├─ practice/
│  └─ ...
│
├─ .gitignore
└─ README.md
```

### `drills/`

Git / GitHub 操作の課題ドキュメントを配置する。

各ドリルには、想定シチュエーション、課題内容、作業の流れ、完了条件、解答例、学習ポイントなどを記載している。  
ファイル名には取り組む順番を表す連番を付けている。

### `practice/`

ドリル内で編集、追加、削除などを行う練習用ファイルを配置する。

HTML / CSS / JavaScript / JSON / Markdown などのファイルを使い、開発作業に近い変更を行える形にしている。  
ソースコードやファイル自体の完成度を目的とするのではなく、差分、コミット、branch、merge、conflict などを確認するための題材として使用する。

### `.gitignore`

ローカル設定、ログ、生成物など、Git で管理しないファイルを設定する。
